# 已知限制

## Hook 标准输出不是事务

CCAutoApprove 的 Hook 是一个短生命周期子进程。Claude Code 启动它，把请求写入标准输入（stdin），再从标准输出（stdout）读取结果。在 Windows 上，这类父子进程通信通常由匿名管道承载；匿名管道是单向的字节流，不提供数据库事务那样的“提交”或“回滚”。可参考 Microsoft 的 [.NET 管道操作文档](https://learn.microsoft.com/en-us/dotnet/standard/io/pipe-operations)。

这意味着：一旦操作系统已经接受了部分 stdout 字节，CCAutoApprove 就无法把这些字节从管道中取回。如果写入过程中发生极少见的外部故障，例如读取方突然退出、管道被关闭或操作系统报告 I/O 错误，程序不能保证撤销已经传出的前缀。

### 我们怎样降低风险

CCAutoApprove 不会边计算边输出。它会先完成以下工作：

1. 解析并验证完整请求；
2. 检查应用进程、心跳和项目范围；
3. 得到最终决定并完成有时限的审计尝试；
4. 在内存中生成完整的 92 字节 Allow JSON；
5. 最后只调用一次同步 stdout 写入。

因此，正常情况下 Claude Code 只会看到两种结果：

- 一个完整、合法的 Allow JSON 对象；
- 零字节输出，随后按原有流程继续人工询问。

如果外部管道恰好在最后一次写入中途损坏，读取方最多得到不完整的 JSON 前缀。这个前缀不是合法 JSON，也不是有效的 Allow 决定；但是，已经被操作系统接收的字节无法由发送方回滚。这是字节流传输边界的固有限制，不是应用层能够实现的事务语义。

### 为什么仍然保留官方 Hook

官方 Hook 提供明确的 stdin/stdout 协议和权限决定边界，也让 Claude Code 在没有完整 Allow 对象时恢复自己的正常处理。与模拟键盘、鼠标或终端选择相比，它更容易验证、限制项目范围、设置超时并安全降级。因此，CCAutoApprove 保留官方 Hook，并通过“内存缓冲 + 最后一次完整写入 + 非完整 JSON 不构成 Allow”来把剩余风险压缩到操作系统传输故障这一外部边界。

README 的安全警告已链接本页；返回 [README](../README.md) 可查看安装与使用说明。

## Claude 设置文件采用并发安全优先，而不是崩溃原子替换

在 Windows 上，`File.Replace` 要替换一个已经存在的路径，目标文件的所有打开句柄都必须允许 delete sharing。允许 delete sharing 又意味着另一个不合作的编辑器可以在 CCAutoApprove 比较完字节后，用同目录临时文件原子替换该路径；原句柄仍指向旧文件对象，随后按路径进行的替换或删除就可能覆盖、删除外部编辑器已经成功提交的新对象。

CCAutoApprove 因而对已经存在的 Claude 设置文件采用安全优先边界：

1. 先在同目录准备完整替换字节，并保留按路径派生的跨进程串行化与有界重试；
2. 用 `FileShare.None` 打开同一个可读写句柄，在该句柄上读取并逐字节比较；
3. 比较成功后仍不释放句柄，直接在同一文件对象上写入完整替换字节并强制刷新；
4. 普通 reader、原地 writer 和 sibling-temp rename writer 在这段成功操作期间都只能得到明确的 sharing/conflict 失败，不能观察截断或部分写入；它们可在句柄释放后重试；
5. 如果普通写入在截断后抛出异常，CCAutoApprove 会在仍持有独占句柄时恢复并刷新比较前的精确原始字节，然后再传播原异常。

原本不存在的设置文件仍使用不覆盖目标的原子同目录移动。条件删除则先在独占比较后把路径原子移动到随机 quarantine sibling，再次核对被移动的精确字节，只删除仍由本次操作拥有的对象。如果外部原子替换恰好赢得“释放独占句柄到移动路径”之间的极小窗口，CCAutoApprove 会把已提交的外部字节移回原路径并拒绝删除；如果原路径又被更晚的 writer 占用，则两个版本都会保留，操作抛出包含 quarantine 恢复路径的错误，不会覆盖任一版本。

### 无法同时提供的保证

普通 Win32 文件 API 不能在持有禁止 delete sharing 的独占句柄时，再对同一路径执行 crash-atomic `File.Replace`。因此，上述“现有文件同句柄改写”明确不保证进程崩溃、系统崩溃或断电级原子性：如果这类不可捕获故障正好发生在截断与完整刷新之间，磁盘上可能留下旧字节、新字节或部分字节，也可能留下 staging/quarantine sibling。正常返回的成功路径会阻止 reader 观察中间态；可捕获的写异常会恢复精确原字节；但崩溃后的恢复仍可能需要使用 `settings.json.ccautoapprove-backup-*` 精确字节备份或相邻恢复文件手工处理。

这是有意选择的安全权衡：不合作的原子 writer 不会被 CCAutoApprove 静默覆盖或删除，代价是放弃现有文件更新的崩溃原子替换保证。
